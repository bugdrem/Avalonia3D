## Avalonia3D 工业看图/打标 Demo — 初始搭建完成

用户需求：.NET 10 + Avalonia 跨平台 3D 文件加载显示 demo，完全支持 AOT，渲染交互对标微软 3D 看图，目标为工业级 3D 打标软件。

### 技术选型（已调研验证）
- Avalonia 12.1.4（官方支持 net10.0 + SkiaSharp 3 + NativeAOT）
- OpenGL 嵌入用 Avalonia 内置 `OpenGlControlBase`（`Avalonia.OpenGL` 程序集，`OnOpenGlInit/OnOpenGlRender/OnOpenGlDeinit` 钩子），无需自建窗口
- `GlInterface` 只暴露约 80 个 GL 入口：无 glLineWidth/glBlendFunc/glPolygonMode/Uniform3f → 线框用 GL_LINES 几何、vec3 uniform 用 mat4 第 4 行编码、无混合纯不透明、SSAA 用 FBO+纹理下采样
- 着色器按 GL 版本自适应：330 core / 150（macOS）/ 300 es / 100 es（关键字降级替换）
- Windows 上 Avalonia 用 ANGLE（GLES3），macOS 桌面 GL 4.1，Linux GLX

### 关键坑（重要）
1. **System.Numerics 是行向量约定**（v*M，平移在第 4 行）；上传 GL 用 transpose=false 后 GLSL 按 `uProj*uView*uModel` 列向量顺序即正确。LookAt 矩阵基向量必须在列中。
2. **System.Numerics 的 CreatePerspectiveFieldOfView 是 DX [0,1] 深度区间**，GL 必须手写 (f+n)/(n-f) 矩阵（[-1,1]）。
3. **射线方向 = right*ndcX*tan*aspect + up*ndcY*tan + ForwardDirection**（视线方向就是 forward，不是 -forward）。
4. **XAML 初始化期间 ComboBox/SelectionChanged 等事件先于构造函数后置代码触发** → 所有事件处理器需要 `_ready` 守卫，否则启动即 NRE（AOT 冒烟测试抓到）。
5. **GLB JSON chunk 可能带 0x00/空格填充**，JsonDocument.Parse 前需裁剪。
6. **OBJ 加载器必须按 (v,vt,vn) 去重顶点**，否则无法线的模型得到分面着色而非平滑着色。
7. **环境**：本机 Windows SDK 在 `D:\Windows Kits\10`（10.0.19041），MSVC 在 `D:\Program Files\Microsoft Visual Studio\18\Enterprise`。AOT 发布前需 export LIB/INCLUDE 指向这两个路径，否则 LNK1181（advapi32.lib 找不到）。沙箱会拦 reg.exe（不影响发布）。

### AOT 冒烟测试发现并修复的问题（全部修复后复验通过）
1. XAML 初始化期间 ComboBox SelectionChanged 先于构造函数后置代码 → 启动 NRE。修复：`_ready` 守卫。
2. **`vec4(aPos, 0.0, 1.0)` 是 5 个分量**（vec3+float+float）→ ANGLE 报 "'constructor' : too many arguments"（错误行号指向 mix 行，具有误导性）。LineVertex 中改为 `vec4(aPos, 1.0)`。
3. 初始渲染帧早于 OnLoaded 加载模型，且相机 Snap 后不再请求帧 → 模型不可见。修复：`PushSceneToRenderer()` 末尾始终 `RequestNextFrameRendering()`。
4. 视图矩阵布局错误（基向量放在行而非列）→ 测试抓出后修复为行向量约定（基在列、平移在第 4 行）。
5. 射线方向符号错误（应为 +ForwardDirection）。
6. GLB JSON chunk 尾部 0x00 填充导致 JsonDocument 解析失败。
7. OBJ 加载器顶点未去重 → 无法线模型得到分面着色；改为 (v,vt,vn) 缓存去重。
8. GlRenderer.Init 重复调用时 _disposed 标志未复位（上下文重建后渲染失效）。
9. GLES 源码里的中文注释疑似触发 ANGLE 解析异常（已全部改英文，虽最终定位为 #8 但保持 ASCII 是最佳实践）。

## 第二轮：鼠标交互修复 + 真实样本模型（用户反馈）

### 1. 鼠标无法交互 — 根因与修复
- **根因**：Avalonia 已知问题（Discussion #10879）——`OpenGlControlBase` 通过 Composition SurfaceVisual 渲染，**不在场景图命中测试数据中**，默认收不到任何指针事件（PointerEntered/Moved/Pressed/Wheel 全部失效）。
- **修复**：`ViewportControl` 实现 `Avalonia.Rendering.ICustomHitTest`，`HitTest(Point)` 把视觉根坐标经 `VisualRoot.TranslatePoint` 转本地坐标后按自身矩形判定。
- **附带修复（验证时发现）**：相机灵敏度严重失调——旋转 2.6 弧度/像素（应 0.008，快 300 倍）、缩放每格 0.16%（应 ~11%）。已改为 0.008 / 0.12（含 ±120 增量归一化），并补 4 个灵敏度单元测试。
- **验证方法**（沙箱内无 GUI 自动化）：PowerShell + SetCursorPos/mouse_event 真实鼠标事件；关键是沙箱的 WorkBuddy 窗口（Chrome_RenderWidgetHostHWND，置顶）会拦截点击，需 `SetWindowPos(blocker, HWND_NOTOPMOST)` + 应用窗口 TOPMOST + 重试循环才能把事件送进应用。PostMessage 经典鼠标消息无效（Avalonia 12 可能启用 mouse-in-pointer，只处理 WM_POINTER*）。已实测：旋转 yaw 平滑变化、平移姿态不变、缩放每格 -11.3%。

### 修复：Linux 下 3D 视口空白（FPS 0）（17:15）
- 症状：Ubuntu（VirtualBox）里程序能跑、UI 正常，但视口全空白、FPS 显示 "--"（零帧）→ OnOpenGlInit/OnOpenGlRender 从未触发
- 根因（Avalonia 已知缺陷 #13879）：OpenGlControlBase.RequestNextFrameRendering() 在 GL 初始化完成前被调用时，旧版实现会把 _updateQueued 置位但 _compositor 为 null，首帧请求永久丢失；新版实现已加 _compositor!=null 保护，但不能假设 12.1.4 带此修复。我们的 OnLoaded→LoadDemoModel→PushSceneToRenderer→RequestNextFrameRendering 正是过早调用（Windows 时序碰巧无害，Linux EGL 初始化更晚即中招）
- 另一可能原因（无法本机复现）：Linux 无 GL 互操作（虚拟机无 3D 加速/缺 Mesa）时 InitializeAsync 返回 false， Avalonia 只写日志、不回调、不报错 → 同样症状
- 修复：
  1. 所有帧请求收敛到 ViewportControl.RequestFrame()（_glReady 前置空操作），PushSceneToRenderer 与 MainWindow 全部改走此入口；OnOpenGlInit 首先置 _glReady
  2. UI 线程 OnTick 兜底：未渲染过首帧前持续 RequestFrame()（初始化前为空操作，不会触发缺陷）
  3. 看门狗：Attach 时启动 1s 定时器，3 秒未完成 GL 初始化则在视口显示深色浮层写明原因（虚拟机 3D 加速/Mesa/xvfb）；初始化失败/上下文丢失同样显示浮层（ViewerSession.ViewportError/HasViewportError）
- 验证：Windows 截图回归（tools/verify-viewport.ps1：视口区 466 种颜色、齿轮+网格正常）；56/56 测试；四平台产物全部重新发布 + AOT 冒烟通过
